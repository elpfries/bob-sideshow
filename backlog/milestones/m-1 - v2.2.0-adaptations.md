## Description

Bring bob-sideshow onto IBM Bob 2.2.0 (`bob-code` 2.2.0, build `1.126.0+bob2.2.0.20260924155054`), which shipped while the whole project was verified on 2.1.0.

Two things moved. The database advanced one migration, to `011_key_value_store`, so all five shipped scripts warn on start even where nothing else changed. And `extension.js` went from 14.7 MB to 10.6 MB under a more aggressive minification that erased the exported identifier names the 2.1.0 notes used as anchors — `SUBAGENT_PRESETS`, `MODEL_TIERS`, `loadWorkspaceRules`, `assessCommandSecurity`, `getBestCommandMatch`, `parseAgentFile`, `featureFlagsSchema`, `isWorkspaceTrusted` and others. Prompt text, settings keys and error messages survive; names do not.

So the milestone is mostly verification, not repair: nothing crashes on 2.2.0. Each fact is found again through the strings that are left, re-anchored on something that will survive the next rebuild, and only then relabelled. A fact that cannot be re-checked is marked with the build it was read on rather than silently renumbered — AGENTS.md requires `VERIFIED_*` to move last.

This is also the first evidence for the assumption m-0 rests on: the minifier does rename its anchors between releases.
