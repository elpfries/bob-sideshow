# Bob 2.2.3 → 2.3.0: what changed in `bob-code`

Companion to [bob-2.1.0-to-2.2.0.md](bob-2.1.0-to-2.2.0.md), which it follows step for step. That page
established what moved between 2.1.0 and 2.2.0; 2.2.0, 2.2.1 and 2.2.3 are the same `bob-code` bundle
apart from one development-only path literal (see its "2026-10-19 update"), so this page compares
2.2.3 with 2.3.0 and nothing in between. Everything bob-sideshow states was read on 2.2.0 and
re-checked unchanged on 2.2.3; the update to 2.3.0 replaced the application in place and every script
now warns. Before any note is re-verified or relabelled, this page establishes what actually moved, and
for each item whether it is a behaviour change, a cosmetic or bundling artefact, or still undetermined,
and which skill or note of this repository it touches.

The rule of the exercise is the one of the previous page: a vanished identifier proves nothing, and
every fact below is anchored on a literal a minifier cannot rename — prompt text, an error message, a
settings key, a method or object-key name — never on a byte offset or a module export name.

**Source tags.** Every statement is about build **2.3.0** (`1.126.0+bob2.3.0.20261026121409`) unless it
says "2.2.3". The tag opening each Evidence cell says where it was read: **[bundle]** the installed
`extensions/bob-code/dist/extension.js` (identical to the frozen copy, compared with `cmp`);
**[db]** a read-only open of `~/.bob/db/bob.db`; **[webview]** the files under `dist/web/`;
**[en.json]** `dist/translations/en.json`; **[manifest]** the extension `package.json` or `product.json`;
**[changelog]** the public changelog; **[stored prompt]** a system prompt or user message stored in the
database by a 2.3.0 task. A literal in backticks is the anchor.

Two lessons of this pair, new since the previous page:

- **A CHANGED verdict can sit on the caller, and an IDENTICAL verdict can sit next to the change.**
  `validateToolExecution` is CHANGED with 29 edits, but the three methods of the approval engine are the
  same text in both builds; what changed is the pipeline that calls them (§ 1). Conversely
  `requiresSecurityApproval` is unchanged while the function that decides it gained a gate (§ 1). The
  anchors added for 2.3.0 cover both; read an anchor together with its neighbours.
- **A literal that leaves an object shows up on no anchor.** The `explore` preset lost its
  `maxTurns:50`; the anchor `maxTurns` reports a different edit. It was found by reading the preset in
  both builds (§ 3).

## The delta

Classes: **behaviour** (Bob does something else), **artefact** (cosmetic, bundling or dependency change;
Bob does the same thing), **undetermined** (cannot be settled from the artefacts at hand). The last
column names the skill or note of this repository the fact touches: `bob-security-model` (with its
`reference/approvals.md`), `bob-override-rules` (templates and hooks), `bob-agent-rules` (with
`reference/injected-rules.md` and `command-migration.md`), `bob-telemetry`, `bob-version`.

**Announced and confirmed in the bundle**: hooks in remote workspaces (`fileSystems`); `PermissionRequest`
and `PermissionResolved`; `mcp.json` in plugins and the global `~/.bob/plugins/<name>/mcp.json`;
`office_edit` with backup; MCP server instructions in the prompt; experimental web search

and active mode in the context; sub-agent turn limits inherited; per-workspace session profile in
`.bob/settings.json`; `maxCost` 0 lifts the cap; stricter paths (the absolute path rule).

**In the bundle, silent in the changelog**: the approval flow moved into a shared class (same gates,
different telemetry for the four always-approved tools); the new command gate for writes to
`.gitignore`/`.bobignore` paths, effective even with command security off; the notice appended to a tool
result when a hook or the user changed its input; observation masking; the `read_file` context-focus
guidance and flag; the `explore` preset losing `maxTurns:50`; the recursive task deletion; the two editor-session
migrations; the five new server flags; the removal of three task import/export commands; the
`UpdateMode` policy; `pinnedModels` and `locale`; the `chart` id/versioning.

**Announced and not located**: "Add-on DevSecOps", "mode selector", "workflow session names", "GitHub issues in
Review" (strings exist, behaviour not read), "MCP tool annotations" (only the SDK schema), "global MCP
servers without a workspace", "`execute_command` that hung", "images above 3.75 MB" (the error sentence now takes the limit from a variable
instead of the literal `3.75 MB`; the handling itself was not read), "skills behind symbolic links", "plugin
skill state", "message lines purged after compaction" (observation masking is the nearest trace),
"background git discovery" (git watcher strings), "`js-yaml` and `lib0`". None of them is something
bob-sideshow states.

## Facts the notes assert that this delta neither confirms nor refutes

For TASK-17.2 to 17.4: re-read these on the build, do not re-word them.

1. **Trust and auto-approval.** Whether an untrusted folder switches auto-approval off in the IDE (§ 2,
   second row) is decided by a value the IDE approval path does not read. Do not write "untrusted
   disables auto-approval" without exercising it.
2. **The `PermissionRequest` merge rule.** "A deny from any handler wins" is the bundled skill text; the
   merge code was not read, and nor was the behaviour with several matching groups.
3. **Web search in the IDE.** The tool is registered under a condition the production IDE does not meet
   as read; nothing was run. Say "present, gated off", not "available".
4. **Tool annotations and the MCP toggle.** The Shell has `Comma-separated list of tools to auto-approve
   while MCP auto-approval is on`; the IDE's own wording ("MCP toggle still wins") comes from the
   `# Configure MCP` text only.
5. **The `fileSystems` default for remote workspaces** is read from the filter; no remote workspace was
   exercised.
6. **Plugin ordering control** carried since TASK-14 (a plugin that has both `rules-<mode>/` and `rules/`)
   is still untested; the loader constants did not change.
7. **Unit prices and `_meta.spend`.** Nothing in the bundle prices a call; the stored shape is still
   `{cost, contextTokens}`.
8. **`general` preset turns.** The 25 is now sourced (`?? 25` in 2.2.x) and is inherited from the parent
   in 2.3.0; a spawned agent's actual limit was not observed.
